1. Introducción

Los servicios de transferencia de ficheros permiten intercambiar archivos entre equipos y administrar directorios remotos. En esta unidad estudiaremos FTP, FTPS y TFTP, sus clientes y la implantación de servidores en Windows Server y Ubuntu Server.

Objetivos

  • Identificar protocolos, puertos y agentes.
  • Distinguir conexiones activas y pasivas y modos ASCII y binario.
  • Interpretar comandos y respuestas.
  • Instalar, configurar y monitorizar servidores con distintos permisos.

2. Protocolo FTP

FTP (File Transfer Protocol), definido en RFC 959, pertenece a la capa de aplicación y utiliza TCP. Permite subir, descargar, listar, renombrar y eliminar archivos, además de crear directorios.

2.1. Características y funcionamiento

El cliente inicia una conexión de control al puerto TCP 21 del servidor. Las operaciones que transfieren datos, como LIST o RETR, requieren una conexión de datos independiente. El intérprete PI gestiona comandos y respuestas; el proceso DTP realiza las transferencias. La interfaz de usuario traduce las acciones del usuario en órdenes.

FTP transmite credenciales y contenido sin cifrar. Debe reservarse para laboratorios aislados o sustituirse por alternativas seguras.

2.2. Tipos de conexión

Modo activo

  1. El cliente comunica su puerto de escucha mediante PORT.
  2. El servidor confirma y recibe una orden de transferencia.
  3. El servidor inicia la conexión de datos, tradicionalmente desde TCP 20.
  4. Al terminar, notifica el resultado por el canal de control.

Modo pasivo

  1. El cliente envía PASV.
  2. El servidor anuncia un puerto de datos disponible.
  3. El cliente inicia la conexión de datos hacia ese puerto.
  4. Se realiza la transferencia y se comunica su finalización.

2.4. Usuarios y grupos. Acceso anónimo

El servidor puede autenticar cuentas del sistema o cuentas específicas del servicio. Los grupos simplifican la asignación de permisos. El acceso anónimo utiliza normalmente el nombre anonymous y permite publicar recursos sin una cuenta personal. Conviene restringirlo a lectura y a un directorio concreto.

2.5. Permisos, cuotas y límite de ancho de banda

Los permisos efectivos dependen tanto de las reglas del servidor FTP como de los permisos del sistema de archivos (NTFS o permisos UNIX y ACL). Una autorización FTP no sustituye los permisos del sistema. Las cuotas limitan el espacio o volumen permitido; los límites de velocidad y sesiones evitan que un cliente monopolice el servicio.

2.6. Modos de transferencia

ASCII (TYPE A) adapta la representación de texto, incluidos los finales de línea. Binario (TYPE I) conserva los bytes y es apropiado para imágenes, ejecutables, ZIP y otros archivos. FTP también contempla representaciones EBCDIC y local, y modos de transmisión stream, block y compressed; no deben confundirse con activo y pasivo.

ArchivoTipo recomendado
TXT de texto planoASCII si se requiere conversión
PNG, ZIP, PDF, EXEBinario

3. Protocolo FTPS

FTPS añade TLS a FTP. El modo implícito inicia el cifrado al conectar, normalmente en TCP 990. El explícito (FTPES) comienza en TCP 21 y negocia TLS mediante AUTH TLS antes de autenticar. Para proteger también los datos se utiliza PROT P. SFTP es un protocolo diferente, basado en SSH, habitualmente TCP 22.

4. Protocolo TFTP

TFTP (Trivial File Transfer Protocol, RFC 1350) utiliza UDP 69 para la petición inicial y puertos negociados para el resto de la transferencia. No proporciona autenticación ni listado de directorios. Se utiliza en arranque por red y distribución de firmware en entornos controlados.

MensajeFunción
RRQLectura
WRQEscritura
DATABloque de datos
ACKConfirmación
ERRORError

Los bloques clásicos son de 512 bytes; un bloque menor señala el final. Si no llega confirmación se retransmite.

5. Cliente FTP

5.1. Consola

Los comandos del cliente no siempre coinciden con los del protocolo. Ejemplo de sesión en una red de laboratorio:

5.2. Navegador web

El libro describe direcciones ftp://servidor; los navegadores modernos habituales han retirado el soporte FTP, por lo que se recomienda un cliente dedicado.

5.3. Explorador

En sistemas compatibles puede introducirse ftp://172.16.0.9 en el explorador de archivos. Las capacidades dependen del sistema.

5.4. Cliente gráfico

FileZilla permite configurar servidor, usuario, contraseña, puerto y protocolo. Su interfaz distingue archivos locales y remotos y muestra la cola y el registro de transferencias. Selecciona FTPS explícito cuando el servidor lo permita.

6.1. Implementación con Microsoft Windows Server

A. Instalación de IIS

Install-WindowsFeature Web-FTP-Server -IncludeAllSubFeature -IncludeManagementTools
Get-WindowsFeature *FTP*

B. Configuración

  1. Crea las cuentas AdminFTP, Informatico1, Informatico2, Contable1 y Contable2 y los grupos Informaticos y Contables. Asigna los miembros.
  2. Crea C:\EJEMPLO_LOCAL y configura permisos NTFS: modificación para AdminFTP e Informaticos; lectura y ejecución para Contables.
  3. En Administrador de IIS, Sitios → Agregar sitio FTP. Indica nombre, ruta, IP 172.16.0.9 y puerto 21. Para el laboratorio aislado selecciona Sin SSL; en producción exige TLS.
  4. En Autenticación FTP activa Básica y desactiva Anónima.
  5. En Reglas de autorización FTP agrega reglas de lectura/escritura para AdminFTP e Informaticos y lectura para Contables.
  6. En Configuración avanzada del sitio fija el límite de conexiones en 50.
  7. Para EJEMPLO_NET crea otro sitio (detén el anterior si comparten IP y puerto), habilita autenticación anónima y básica y autoriza lectura a anónimos y lectura/escritura a AdminFTP. Ajusta NTFS también para la identidad anónima.
  8. Configura el rango pasivo en Compatibilidad con firewall FTP y permite TCP 21 y el rango de datos en el firewall.

C. Administración y monitorización

Get-Service ftpsvc
Restart-Service ftpsvc
Get-Website
netstat -ano

Consulta Sesiones actuales de FTP y Registro FTP en IIS. Los logs suelen estar en C:\inetpub\logs\LogFiles.

Actividad propuesta

Crea un sitio para tres departamentos: cada grupo modifica su carpeta y lee las demás; el gerente modifica todas.

6.2. Implementación con Ubuntu Server (ProFTPD)

A. Instalación

sudo apt update
sudo apt install proftpd-basic -y
sudo cp /etc/proftpd/proftpd.conf /etc/proftpd/proftpd.conf.bak

En versiones donde el paquete anterior no esté disponible, comprueba el paquete proftpd-core. Edita /etc/proftpd/proftpd.conf. Conserva las directivas de distribución necesarias y evita duplicar configuraciones.

B. Escenario EJEMPLO_LOCAL

sudo groupadd informaticos
sudo groupadd contables
sudo useradd -M -s /bin/false -g informaticos informatico1
sudo useradd -M -s /bin/false -g informaticos informatico2
sudo useradd -M -s /bin/false -g contables contable1
sudo useradd -M -s /bin/false -g contables contable2
sudo useradd -M -s /bin/false adminftp
sudo passwd adminftp
# Repetir passwd para las demás cuentas
sudo mkdir -p /EJEMPLO_LOCAL
sudo chown adminftp:informaticos /EJEMPLO_LOCAL
sudo chmod 2775 /EJEMPLO_LOCAL

Adaptación del ejemplo del libro: nombres en minúscula y permisos más restrictivos que 777. El grupo contables puede leer mediante los permisos de otros; la regla FTP restringe el acceso a las cuentas autorizadas.

ServerName "EJEMPLO LOCAL"
ServerType standalone
DefaultServer on
Port 21
MaxClients 50
DefaultRoot /EJEMPLO_LOCAL
RequireValidShell off
Umask 002
PassivePorts 50000 50100
<Limit LOGIN>
  AllowUser adminftp
  AllowGroup OR informaticos,contables
  DenyAll
</Limit>
<Directory /EJEMPLO_LOCAL>
  <Limit WRITE>
    AllowUser adminftp
    AllowGroup informaticos
    DenyAll
  </Limit>
  AllowOverwrite on
</Directory>

C. Escenario EJEMPLO_NET

sudo mkdir -p /EJEMPLO_NET
sudo chown adminftp:root /EJEMPLO_NET
sudo chmod 755 /EJEMPLO_NET

Como configuración alternativa al escenario local, sustituye sus bloques de acceso por los siguientes. Comprueba que existe la cuenta ftp y que no hay otro bloque Anonymous activo.

ServerName "EJEMPLO NET"
ServerType standalone
DefaultServer on
Port 21
MaxClients 50
DefaultRoot /EJEMPLO_NET
RequireValidShell off
Umask 022
PassivePorts 50000 50100
<Limit LOGIN>
  AllowUser adminftp
  DenyAll
</Limit>
<Anonymous /EJEMPLO_NET>
  User ftp
  Group nogroup
  UserAlias anonymous ftp
  MaxClients 10
  <Limit LOGIN>
    AllowAll
  </Limit>
  <Limit WRITE>
    DenyAll
  </Limit>
</Anonymous>

D. Validación y monitorización

sudo proftpd -t
sudo systemctl restart proftpd
sudo systemctl status proftpd
sudo ss -ltnp
ftpwho
ftptop
sudo journalctl -u proftpd

Si UFW está activo, permite TCP 21 y TCP 50000:50100 desde la red de laboratorio. Las directivas TransferLog, SystemLog y ExtendedLog permiten registrar transferencias y actividad.

TransferLog /var/log/proftpd/xferlog
SystemLog /var/log/proftpd/proftpd.log

Comprueba con cada cuenta que las operaciones permitidas funcionan y las prohibidas fallan. Si se utiliza PAM, revisa sus restricciones de shell y autenticación.

📝 Supuestos prácticos

Práctica 1. Ubuntu Server

Implanta EJEMPLO_LOCAL y EJEMPLO_NET según la matriz anterior. Verifica autenticación, lectura, escritura y denegaciones mediante capturas. Configura después un máximo de cuatro clientes e intenta conectar cinco.

Práctica 2. Windows Server

Reproduce ambos escenarios con IIS y comprueba permisos NTFS, reglas FTP, sesiones y logs.

Práctica 3. Clientes y análisis de tráfico

Con FileZilla y consola, crea fotos, sube vacio.txt, descárgalo y elimina el archivo y el directorio. En una red aislada captura tráfico propio con Wireshark, filtro ftp o ftp-data, y relaciona órdenes y respuestas. Compara con una conexión FTPS.
